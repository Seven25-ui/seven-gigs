How to Connect a Custom Domain to Your GitHub Pages Site

Nov 6, 2026 · 4 min read

GitHub Pages gives you a free website at an address like yourname.github.io. It works well, but a custom domain looks more professional and is easier for clients and visitors to remember. It is also a better choice if you plan to apply for ads or want a brand people can trust. The good news is that connecting a domain to GitHub Pages is free on the GitHub side, and it only takes a few settings.

What you need

- A GitHub repository that already publishes a site with GitHub Pages
- A domain name that you own, bought from any registrar
- Access to the DNS settings of that domain

Step 1: Decide between a main domain and a subdomain

A main domain looks like example.com. A subdomain looks like blog.example.com or gigs.example.com. If you already use your main domain for another site, such as a portfolio, a subdomain is the easiest choice because you can keep both sites running at the same time.

Step 2: Add the custom domain in GitHub

Open your repository on GitHub and go to Settings, then Pages. Find the field named Custom domain, type your domain or subdomain, and save. GitHub will try to check it. It is normal to see a DNS warning at this point because you have not set up the DNS records yet.

Step 3: Add the DNS records at your registrar

Log in to the place where you manage your domain and open the DNS settings.

For a subdomain, add a CNAME record. The name is the subdomain part, for example blog or gigs, and the value is your GitHub address, which looks like yourusername.github.io. Do not add the repository name to the value.

For a main domain, add four A records that point to GitHub's servers: 185.199.108.153, 185.199.109.153, 185.199.110.153, and 185.199.111.153. Some people also add a CNAME record for www that points to yourusername.github.io, so both versions of the address work.

Always double check these values on GitHub's official documentation before you save them, because hosting details can change over time.

Step 4: Wait for DNS to update

DNS changes can take a few minutes, and sometimes up to a day. During this time your site may not load on the new address. This is normal. You can check again after an hour.

Step 5: Turn on HTTPS

Go back to Settings, then Pages. Once GitHub has verified your domain, you will see a checkbox named Enforce HTTPS. Turn it on. HTTPS makes your site secure, and many services expect it. If the checkbox is greyed out, wait a little longer and refresh the page. GitHub needs time to create the certificate.

Step 6: Make sure the CNAME file stays in your repository

When you save a custom domain, GitHub usually adds a file named CNAME to your repository. If your site is built by a GitHub Action or a script, make sure that file is included in the final output. If it disappears after a build, your custom domain will quietly stop working.

Common problems and fixes

- The site shows a 404 page. Check that your CNAME or A records are correct and that the custom domain in GitHub matches exactly.
- HTTPS is not available. Wait for the certificate to finish, or remove the domain and add it again.
- The old address still shows. Clear your browser cache or try a private window.
- Links and images are broken. If you used full links that include the old address, change them to relative links or to your new domain.
- Search and sitemap files are wrong. If you have a sitemap or canonical links, update them to the new domain.

After the domain works

Update every place where you shared your old address, like your Upwork profile, your social media, and your portfolio. Keep the old github.io address working too, because GitHub will redirect it to your new domain.

A custom domain does not make a website good by itself, but it makes it look more serious and gives you full control of your address. If you ever change where your site is hosted, you can keep the same domain and only change the DNS records. That is one of the biggest reasons to start with your own domain early.
