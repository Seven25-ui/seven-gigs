.gitignore for Beginners: Keep Secret Files Out of GitHub (PowerShell Guide)

Nov 27, 2026 · 3 min read

When you push a project to GitHub, Git uploads every file it tracks. That can include things you never meant to share, like a .env file with passwords, log files, or a huge node_modules folder. A .gitignore file tells Git which files to leave alone. It takes two minutes to set up and can prevent a lot of pain.

This guide uses PowerShell on Windows, but the Git commands are the same on other systems.

1. Open your project folder

Open PowerShell and go to your project:

cd C:\Users\YourName\Desktop\my-project

Replace the path with your own folder.

2. Create the .gitignore file

New-Item .gitignore -ItemType File

If the file already exists, you will see an error. That is fine, just open it in the next step.

3. Add the files to ignore

Open it in Notepad:

notepad .gitignore

Then type one pattern per line, for example:

.env
.env.local
node_modules/
*.log
secrets.json

What these mean: a name like .env ignores that file. A name ending with a slash ignores a whole folder. A star works as a wildcard, so *.log ignores every file ending in .log. Save the file and close Notepad.

Tip: it is safest to edit the file in Notepad. In older versions of Windows PowerShell, writing to a file with the > symbol can save it in an encoding that Git does not read correctly.

4. Check that it works

git status

The ignored files should not appear in the list. To see why a file is ignored, run:

git check-ignore -v .env

If the command prints a line, the file is being ignored.

5. If the file was already tracked

.gitignore only affects files that Git is not tracking yet. If you already committed .env before, Git will keep tracking it. Tell Git to stop tracking it, but keep the file on your computer:

git rm --cached .env

For a folder, add -r:

git rm -r --cached node_modules

6. Commit and push

git add .gitignore
git commit -m "Add gitignore and stop tracking secret files"
git push

7. If a secret was already pushed

This is the most important part. Removing the file now does not erase it from your Git history, and anyone who looked at the repository could have copied the key. If an API key, token, or password was ever pushed, treat it as exposed:

- Go to the service that issued the key
- Revoke or delete it
- Create a new key
- Put the new key in a file that is ignored, never in the public code

8. A note about GitHub Pages

A site on GitHub Pages is public, and the browser can read all its HTML and JavaScript. A .gitignore cannot hide a key that your front-end code needs. For private keys, use a small backend or a serverless function, and keep the key there.

Quick checklist

- Create .gitignore before your first commit
- Add .env, node_modules/, and log files
- Run git status before every push
- If a secret leaks, rotate it right away

Good habits like this keep your projects, and your clients' projects, safe.
