How to Get a Telegram Alert When Your n8n Workflow Fails

Nov 20, 2026 · 3 min read

An automation that works today can fail tomorrow. An API changes, a login expires, or a spreadsheet gets renamed. If nobody notices, leads are lost and reports are not sent. For client work especially, you want to know the moment something fails. n8n has a simple way to do this: an error workflow.

The idea

You create a second workflow that starts with an Error Trigger node. Then you tell your main workflow to use it as its error workflow. When the main workflow fails, n8n runs the error workflow and sends you the details. Here we will send them to Telegram.

What you need

1. n8n running (self-hosted on your PC or in the cloud)
2. A Telegram bot and your chat ID (you can create a bot with BotFather)
3. Telegram credentials saved in n8n
4. At least one workflow you want to protect

Step 1: Create the error workflow

Create a new workflow and name it clearly, for example "Error alert to Telegram". Add an Error Trigger node as the first node. This node has no settings. It simply starts the workflow when another workflow reports a failure.

Step 2: Add a Telegram node

Add a Telegram node and choose the action to send a message. Select your credentials and paste your chat ID. Keep your bot token inside n8n credentials, never inside the workflow text.

Step 3: Write a useful message

The Error Trigger gives you details about the failed run. You can insert them with n8n expressions. A good alert includes:

1. The name of the workflow that failed
2. The error message
3. A link to the failed execution
4. The time

An example message:

Workflow failed: {{ $json.workflow.name }}
Error: {{ $json.execution.error.message }}
Open: {{ $json.execution.url }}

The exact field names can change between n8n versions, so run a test and look at the output of the Error Trigger node to see what is available on your version.

Step 4: Connect it to your main workflow

Open the workflow you want to protect and open its Settings. Find the option named Error Workflow and choose the one you just created. Save the workflow. Do this for every important workflow. One error workflow can serve all of them.

Step 5: Test it

Make a test workflow that fails on purpose, for example with a node that points to a wrong address. Set its Error Workflow to your alert workflow, activate it, and let it run. The error workflow is meant for automatic runs of active workflows, so a manual test button may not trigger it. When it works, you should receive a Telegram message within seconds.

Step 6: Activate the error workflow

Make sure the error workflow itself is saved. Check in the executions list that it ran. If nothing arrives, check three things: the Telegram credentials, the chat ID, and whether you pressed Start in the chat with your bot.

Ideas to improve it

1. Send alerts to a group so a team can see them
2. Add the client's name to the message, so you know which project is affected
3. Log each failure to a Google Sheet, so you can see patterns
4. Add a daily summary of failures instead of many messages
5. Include a short note on what to check first, such as expired credentials

Remember when n8n runs on your own PC

If your n8n runs on your computer, it cannot alert you when the computer is off. For client projects, host n8n on a server that stays online. An alert is only useful when the system that sends it is running.

The bottom line

Error alerts take about ten minutes to build and make your automations much more professional. Clients trust a freelancer who finds problems before they do. Add an error workflow to every project, and mention it in your proposals as part of your standard setup.
