Git Basics for Beginners: Clone, Commit, Push, and Pull in PowerShell

Nov 17, 2026 · 4 min read

Git is a tool that keeps the history of your files, and GitHub is a website that stores Git projects online. If you build websites or small apps, you will meet both soon. You do not need to learn everything at once. A few commands cover most daily work. This guide uses PowerShell on Windows, but the commands are the same on Mac and Linux.

Step 1: Check that Git is installed

Open PowerShell and type:

git --version

If you see a version number, Git is ready. If not, install it from the official Git website, then close and open PowerShell again.

Step 2: Set your name and email

Git writes your name and email in every commit. You only need to do this once on a computer:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Use the same email that is connected to your GitHub account, so that your commits are linked to you.

Step 3: Clone a repository

Cloning downloads a copy of a project to your computer. Go to the folder where you want it, then run:

cd $HOME\Documents
git clone https://github.com/username/project-name.git
cd project-name

Replace the address with the one from the green Code button on your repository page. The last command moves you inside the project folder.

Step 4: See what changed

After you edit files, check the state of your project:

git status
git diff

git status lists the files that changed. git diff shows the exact lines that changed. Reading these before you save is a good habit, because you can catch mistakes early.

Step 5: Stage and commit your changes

A commit is a saved snapshot with a short message. First you choose what goes into it, then you save it:

git add -A
git commit -m "Describe what you changed"

The message should be short and clear, such as "Fix contact page link" or "Add new blog post page." Your future self will thank you.

Step 6: Pull before you push

If other people, or automatic tools, change the same repository, your computer may be behind. Download the latest changes first:

git pull --rebase

This puts your new commits on top of the latest version. It avoids many common errors.

Step 7: Push to GitHub

Now send your commits to GitHub:

git push

The first time, a browser window may open so that you can sign in. After that, the page on GitHub shows your changes. If your site uses GitHub Pages, the live website updates after a minute or two.

The everyday routine in short

git pull --rebase
# edit your files
git status
git add -A
git commit -m "Your message"
git pull --rebase
git push

Common errors and what they mean

- Updates were rejected: the online version has newer commits. Run git pull --rebase, then try git push again
- Merge conflict: two changes touched the same lines. Open the file, look for the markers that Git inserted, keep the correct text, remove the markers, then add and commit again
- Not a git repository: you are in the wrong folder. Use cd to go into the project folder
- Authentication failed: sign in again, and check that your GitHub account has access to the repository

Keep secrets out of Git

Never commit passwords, private keys, or secret tokens, especially in a public repository. Create a file named .gitignore and list files that should be skipped, such as .env. If you pushed a secret by mistake, treat it as exposed and create a new one, because deleting it from the latest file is not enough.

Useful extra commands

git log --oneline
git restore filename

git log --oneline shows a short history of commits. git restore filename throws away your unsaved changes in one file, so use it carefully.

A good habit to build

Make small commits often, and write clear messages. Pull before you start working and before you push. If something goes wrong, do not panic. Read the message, check git status, and search for the exact error text.

Final thoughts

Git feels strange for the first week, then it becomes automatic. Learn clone, status, add, commit, pull, and push, and you can already work on real projects. The rest you can learn when you need it.
