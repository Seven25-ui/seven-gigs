Supabase for Beginners: A Free Database for Your First Project

Nov 1, 2026 · 3 min read

When I started building small projects like a blog, a movie site, and a support chatbot, I needed a place to store data. Setting up my own server felt too heavy. Supabase solved that for me, and it has a free plan that is enough to learn and build your first projects.

What is Supabase?

Supabase is an online database with a friendly dashboard. You create tables, like spreadsheets, and your website or app can read and write data through a simple connection. It also has login features, so you can make an admin page.

What I used it for

- The posts on this blog
- A movie and TV website
- A knowledge base for a RAG support chatbot

Free plan limits and features change from time to time, so check the Supabase website for what is included today.

Step 1: Create a project

1. Go to supabase.com and sign up.
2. Click New project.
3. Choose a name, a strong database password, and a region close to your visitors.
4. Wait a minute or two while it sets up.

Save your database password in a safe place. You will not see it again.

Step 2: Create a table

1. Open the Table Editor from the left menu.
2. Click New table and give it a name, like posts.
3. Add columns, for example: title, content, and published.
4. Save the table.

Think of a table like a spreadsheet. Each column is a heading, and each row is one item, such as one blog post.

Step 3: Add some data

In the Table Editor, click Insert row and fill in the fields. Do it by hand first, so you can see how the data looks before you connect anything.

Step 4: Find your connection keys

Open Project Settings, then API. You will see two things you need:

- The Project URL
- The anon public key

The anon key is meant to be used in a website, so it is safe in your front-end code. The service role key is different. It is private, so never put it in a website, a public repo, or a chat.

Step 5: Turn on Row Level Security

Row Level Security, or RLS, decides who can read or change your data. This step is important. Without good rules, strangers could change your table.

A simple setup for a blog: everyone can read published posts, and only you, after logging in, can add, edit, or delete.

Step 6: Connect it to your website

Add the Supabase library to your page, then use your Project URL and anon key to create a client. After that, you can ask for rows from your table and show them on the page. A basic read looks like this:

const { data, error } = await sb
  .from("posts")
  .select("title, content")
  .eq("published", true);

Mistakes to avoid

- Putting the service role key in public code
- Skipping RLS because it feels confusing
- Forgetting to save the database password
- Building everything before testing one small table

What to build next

Start with something small: a to-do list, a guest book, or a mini blog. Once you can save and show data, you can move to logins, file storage, and even AI features like a chatbot that answers from your own data.

One working table is enough to start. Build the small thing, break it, fix it, and you will learn faster than from any video.
