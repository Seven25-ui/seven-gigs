How to Test a Webhook From PowerShell Without Installing Anything

Nov 24, 2026 · 2 min read

When you build an automation with a webhook, such as an n8n workflow, you need a way to send test data to it. You do not have to install any extra tool. Windows PowerShell can already do this with a built-in command. This short tutorial shows you how.

1. What is a webhook?

A webhook is a web address that waits for data. When something sends a request to that address, your workflow starts. To test it, you just need to send a request yourself.

2. The simplest test

Open PowerShell and run this line. Replace the address with your own webhook URL:

Invoke-RestMethod -Method Post -Uri "http://localhost:5678/webhook-test/lead" -ContentType "application/json" -Body '{"name":"Ana","email":"ana@example.com","budget":800}'

Here is what each part does:

- Invoke-RestMethod sends the request and shows the response.
- -Method Post says we are sending data.
- -Uri is the webhook address.
- -ContentType tells the server that we are sending JSON.
- -Body is the data itself.

3. Build the data in a cleaner way

A long JSON string is easy to break. A neater way is to build the data first:

$data = @{ name = "Ana"; email = "ana@example.com"; budget = 800 }
$body = $data | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "http://localhost:5678/webhook-test/lead" -ContentType "application/json" -Body $body

Now you can change one value, like the budget, and run it again.

4. See the status code

Sometimes you want to know whether the request worked. Use Invoke-WebRequest instead:

$r = Invoke-WebRequest -Method Post -Uri "http://localhost:5678/webhook-test/lead" -ContentType "application/json" -Body $body
$r.StatusCode

A status code of 200 usually means it worked.

5. Catch errors

If the webhook is not listening, PowerShell shows an error. You can handle it like this:

try {
Invoke-RestMethod -Method Post -Uri "http://localhost:5678/webhook-test/lead" -ContentType "application/json" -Body $body
} catch {
Write-Host "Request failed:" $_.Exception.Message
}

6. n8n tip: test URL and production URL

In n8n, the test URL works only while the Webhook node is listening for a test event. The production URL works after you activate the workflow. If you get a 404 error, check which URL you are using and whether the node is listening.

7. Common problems

- The address is wrong. Check the path at the end of the URL.
- The workflow is not active, but you used the production URL.
- You forgot the content type, so the server does not read your JSON.
- The data has a typo, such as a missing quote.

8. Test more than once

Send at least two different examples, for example a high budget and a low budget. This helps you check that every branch of your workflow works.

With one line of PowerShell, you can test a webhook in seconds, and you can use the same method for your client projects.
