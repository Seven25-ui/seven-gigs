Basic SQL for Beginners: Read and Change Data in Supabase

Nov 20, 2026 · 3 min read

If you use Supabase, you can manage your data in the Table Editor with clicks. But SQL is faster for many tasks, such as adding several rows at once or fixing a typo in many places. SQL looks strange at first, but a few commands cover most daily work.

All examples use a table called posts with the columns id, title, category, and published. Replace the names with your own.

Where to run it

In your Supabase project, open the SQL Editor from the left menu. Paste a command, click Run, and read the result below. The SQL Editor runs with strong permissions, so it can ignore the Row Level Security rules that protect your public website. Be careful, because mistakes are real.

1. SELECT: read data

SELECT shows rows from a table.

select * from posts;

The star means all columns. To see only some columns:

select title, category from posts;

2. WHERE: choose which rows

WHERE filters the rows. Text values go inside single quotes.

select title from posts where category = 'Tutorials';

You can combine conditions with and, or:

select title from posts
where category = 'Tutorials' and published = true;

3. ORDER BY and LIMIT

To see the newest rows first and only a few of them:

select title, created_at from posts
order by created_at desc
limit 5;

4. Count and group

To count rows in each category:

select category, count(*) from posts
group by category
order by category;

This is also a quick way to find a category with a spelling mistake.

5. INSERT: add rows

INSERT adds new rows. List the columns, then the values in the same order:

insert into posts (title, category, published)
values ('My first post', 'Tutorials', false);

You can add several rows by separating them with commas.

6. UPDATE: change rows

UPDATE changes existing rows. Always include WHERE, or you will change every row in the table.

update posts
set published = true
where title = 'My first post';

7. DELETE: remove rows

DELETE removes rows, and there is no undo button in the editor. Again, use WHERE.

delete from posts where title = 'My first post';

The safety habit that saves you

Before every update or delete, run a select with the same WHERE condition first:

select * from posts where category = 'AI tools';

Look at the rows that come back. If they are the ones you want to change, copy the same WHERE into your update:

update posts set category = 'AI Tools' where category = 'AI tools';

This simple check prevents most accidents.

Other safety tips

1. Never run update or delete without WHERE
2. Make a backup or export the table to CSV before a big change
3. Test on a few rows first
4. Do not paste secret keys or passwords into the editor or into shared notes
5. Keep Row Level Security turned on for tables that your website reads

Common errors

1. Syntax error: check for missing commas and quotes
2. Relation does not exist: the table name is wrong, or it is in another schema
3. Column does not exist: check the spelling of the column name
4. Text values need single quotes, not double quotes

What to learn next

When these commands feel easy, try joins to combine two tables, indexes to make searches faster, and constraints to stop wrong values from entering your data. Each one builds on what you just learned.

The bottom line

Start with select and where. Add insert, update, and delete when you feel comfortable, and always check with a select first. A little SQL makes your data much easier to manage, and it is a skill that clients value.
